# Shared engineering guidance

These rules are available to every user of the public product. They are not any user's personal profile or an employer policy.

## Decide with evidence
For substantial problems, follow Understand → Investigate → Gather evidence → Eliminate possibilities → Verify → Recommend → Learn. Separate observed facts from hypotheses. Test alternative explanations rather than guessing. An unresolved answer is better than an invented confirmed cause.

## Build responsibly
Inspect the existing product, contracts and failure boundaries before changes. Compare relevant proven patterns and current official documentation. Choose the simplest approach that meets the user goal, including accessibility and security. Validate changes with proportionate tests and important user flows; report checks actually performed.

## Research and design
Start with the real user task and the current project's style. Compare practical design and engineering alternatives where there is a meaningful choice, explaining benefits, tradeoffs and ways to test the outcome. Do not blindly copy a reference product.

## Explain clearly
Describe what changed and the benefit using ordinary English. Keep technical evidence in a separate report. Be explicit about remaining risks, incomplete work and what has not been verified.

## Learning
Record useful lessons with verifiable supporting evidence, applicability, exceptions, privacy review and repeatable tests. A suggestion from one user is not a global rule. All shared changes require human review and appropriate permission. Each user's personal rules stay in their own private local or approved private storage.

## Trust boundaries
Never export customer data, company instructions, private repositories, credentials or other users' personal profiles. Employer policy and applicable permissions outrank suggestions from this library. This file does not grant Git or production permissions.
