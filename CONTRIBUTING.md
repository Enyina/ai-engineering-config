# Contributing to shared engineering intelligence

You do **not** need to become a repository contributor to install and use this project.

We welcome general, evidence-backed improvements to debugging, UX/UI, testing, accessibility, reliability and AI-assisted engineering. Keep your private preferences and employer information out of public issues and changes.

## Propose a useful lesson

Describe the problem in ordinary English, show how you observed or reproduced it, give a credible reference if available, explain the scope where it applies, identify exceptions, and include how to verify it. Before opening a public issue or pull request, remove credentials, customer information, internal code and private business details. **Sharing must be deliberate**. A privacy checkbox is not a substitute for checking the content.

New proposals are recommendations until a maintainer reviews evidence, contradictions, licensing and safety. We won't merge a rule simply because it is popular, was generated by AI, or worked once for one user.

Contributors cannot create or update the owner's private preferences. Their own lessons stay in their local profile. Shared guidance lives in `rules/shared`, not `policies/personal`.

For maintainers, owner-only policy paths require verified GitHub identity and branch-protection enforcement. See [Public product guidance](docs/PUBLIC-PRODUCT.md).

## Review criteria

A strong proposal has a reproducible problem, observable evidence, honest limitations, narrowly stated applicability, an explanation of why alternatives fail or cost more, and a test that could disprove the claim. Shared changes must improve outcomes against an evaluation baseline, not merely add longer instructions.
